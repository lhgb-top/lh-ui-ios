# Введение

**lh-ui-ios** — реализация iOS-стороны **нативного направления** семейства lh-ui: библиотека UI-компонентов на **Swift + SwiftUI**.

## Положение в семействе

```
                        ┌── направление web: share (TS core + SCSS) → plus / vue2 / react / uniapp
семейство lh-ui (один бренд) ─┤
                        └── направление native: core (токены JSON + контракты + codegen) → android / ios / harmony / windows
                                                                   ↑ этот репозиторий
```

- **Центр сборки**: `lh-ui-core` — единый источник токенов нативного направления (`tokens/*.json`), контракты компонентов (`specs/`), золотые сценарии (`cases/`) и инструменты codegen. Он генерирует скелет токенов на Swift (`LhTokens` / `LhDarkTokens` / `LhShadow`), но **не генерирует никакой реализации UI**.
- **Задача этого репозитория**: писать SwiftUI View вручную, подключать темы (внедрение через Environment), определять перечисления пропов и значения по умолчанию, переводить золотые сценарии в XCTest.
- **Независимость от направления web**: нет зависимости от `@lh-ui/share`, релизы не связаны друг с другом. Визуальная согласованность поддерживается вручную согласно *Базовому стандарту языка дизайна*.

## Язык дизайна

Тема в китайском стиле: основной цвет — синий «цинхуаци» (`#2B4C7C`), фон — белый цвета бумаги «сюаньчжи» (`#FAF6F0`), успех — зелёный «сунхуа», предупреждение — жёлтый «тэнхуан», опасность — киноварь «чжуша»; стек серифных шрифтов (Noto Serif SC → STSong → SimSun). Все визуальные значения — токены, в компонентах нет ни одного литерала.

## Почему SwiftUI

- Декларативный UI первого класса на платформе, концептуально симметричный Compose / ArkUI — межплатформенные контракты легче выравнивать
- Подключение в один клик через SPM: никакого JS-рантайма, никаких мостовых слоёв
- `#Preview` — это документация, `View` — это компонент: опыт разработки симметричен SFC из направления web
